# Long-history benchmark: track T1 at 2,000 sessions after roadmap P2-13 (2026-11-23, Claude Sonnet via the Claude Code CLI, commit 7aceafe)

Track T1 (needle at scale) on a fresh seed, 15, at 2,000 seeded sessions only: 12 tasks, three arms, one repetition, **36 real agent sessions, no probes, no re-runs, none excluded.** Aggregates only; event streams, stores and working directories stayed outside the repository.

**What this is.** One measurement, with one agent, one model, one repetition and 12 tasks, of the retrieval and presentation changes of roadmap P2-13 ([the offline record](2026-11-22-offline-retrieval-p2-13.md), which used a scripted reader only). The previous real-agent record at this size is [the seed-13 re-measure](2026-11-22-t1-remeasure-033a9f0.md), made before those changes. A pass is a hidden check passed by one agent on a small synthetic fixture, not evidence of real-task quality, and a seeded history is not a lived one. With 12 tasks and two comparisons, 7 wins against none is the least that passes after Holm correction (p = 0.0156, 0.031 corrected); 6 against none gives 0.031 raw and 0.0625 corrected.

## Design, fixed before the first session

- Arms (three): `memoryking` (exactly what `memoryking setup claude-code` installs at this commit: start, pre-compact and session-end hooks, the prompt-time recall hook, the lean bridge with `alwaysLoad`), `log` (raw transcripts to `grep`), `notes` (the bounded extractive notes file). 12 tasks x 3 arms = 36 sessions, the whole approved budget.
- Seed 15 had never been generated or read before this run (seeds 11 to 14 were not used). One group of twelve tasks at 2,000 sessions.
- **Analysis, fixed before the run.** Primary, two comparisons, Holm-corrected over two: `memoryking` against `log` and against `notes`, exact two-sided sign test paired by task (12 tasks, ties dropped). Wilson 95% intervals per arm. Descriptive only (different seeds, so no test): this run's numbers beside seed 13 and seed 11 at 2,000 sessions. Per run: pass or fail and failure class, input, cache and output tokens, seconds, memory characters in the context. For `memoryking` also whether the prompt hook fired and how many characters it injected; whether its injection carried each needle sentence; how many times the agent called `recall`, with which of the new parameters (`offset`, `match`) if any, and whether a `recall` result carried the needle; and a class for every failure (never surfaced, surfaced but not used, wrong value used, task error), with the needle sentences as the generator states them (the corrected matching of the seed-13 analysis: letters and digits only, the sentence `hookprobe` defines). Whatever it shows is reported, including no gain or a loss.
- Limits fixed: at most 36 sessions, model `sonnet` only, up to four in parallel, the same agent flags, allowed tools, isolation and scope sentence as the earlier runs, a shuffled order (fixed seed) across tasks and arms, a restartable driver with a durable ledger so that no session is started twice, a usage-limit refusal waited out for up to two hours.

## Isolation evidence

- A fresh empty `HOME` per session, a scrubbed environment, a working directory named after the task's project that holds only the repository and the arm's own files, `--strict-mcp-config`, auto-memory off. In all 36 streams the init event shows the same model, the same CLI and `acceptEdits`, and exactly the arm's own tool servers: the `memoryking` server connected in the 12 MemoryKing runs, none in `log` and `notes`. No run timed out or had an error result; every session returned a result event.
- Denied commands (a Bash command that wrote through a heredoc or read outside the directory): 9 of 12 `log` runs (it works by shell commands), 2 of 12 `memoryking`, none in `notes`. One MemoryKing run (batch-export) was denied a heredoc write, then wrote its file with the edit tool and finished normally; its failure is a memory failure, below. A denial is not a harness exclusion, and none was excluded.

`memoryking` against each other arm, exact two-sided sign test on the tasks where the arms differ (ties dropped), Holm correction over the two primary comparisons.

| --- | ---: | ---: | ---: | ---: | ---: |
| `log` | 2 (id-format, port-config) | 4 (batch-export, money-rounding, net-timeouts, retry-policy) | 6 | 0.6875 | 0.6875 |

**What is and is not distinguishable.** MemoryKing is ahead of the bounded notes file (which holds nothing of a 2,000-session history by design) on 7 tasks to none: the only comparison below 0.05, and it is the weakest test of the product. Against the raw transcripts there is no difference this design can detect: `log` is ahead on more tasks (4 against 2, p 0.69), as on every earlier seed; with 12 tasks only a gap of 7 to 0 could show.

## `memoryking` failures, classified

Every failed run was classified from its event stream with the rule of the earlier records: **never surfaced** (no needle sentence of a failing slot is in any hook output or tool result the model was shown), **surfaced but not used**, **wrong value used**, **task error unrelated to memory**. A run with any slot never surfaced is counted never surfaced.

| Arm | Failed | never surfaced | surfaced, not used | wrong value used | task error |
| --- | ---: | ---: | ---: | ---: | ---: |
| `memoryking` | 4 | 1 | 2 | 1 | 0 |
| `log` | 2 | 2 | 0 | 0 | 0 |
| `notes` | 11 | 11 | 0 | 0 | 0 |

- **Never surfaced (1): t1-retry-policy.** The base delay was in no hook or `recall` result; the agent called `recall` twice, wrote 250 ms and said the delay was its own guess.
- **Surfaced but not used (2): t1-money-rounding and t1-net-timeouts.** Both needles of each task were in a result, among records about the same attribute of other components or earlier values; the agent wrote no code and said the records contradicted each other (net-timeouts) or did not name invoice amounts clearly enough (money-rounding).
- **Wrong value used (1): t1-batch-export.** The batch size needle was in a `recall` result, and the agent used 100, which it called "a placeholder I picked myself", with a note asking for confirmation. By the fixed rule an observed value that is not the needed one is "wrong value used" (it was a default, not a value read from a stale record).

`log`'s two failures (id-format, port-config) were each a slot never surfaced by `grep`. The notes file's eleven are empty by design.

## Harness faults, exclusions and regrades

1. **No harness fault was found before or during the run**, so no harness fix and no new test were made. The driver and the analysis scripts live outside the repository, as before; they are the seed-13 ones with the seed, arms, session ceiling (36) and shuffle seed changed, the paths moved, the paired comparison reduced to two with Holm over two, and a count of the `offset` and `match` parameters and of `recall` results that carry a needle added to the `memoryking` analysis.

## Limits of this run

One agent, one model, one CLI, one repetition, 12 tasks, one size; seeded histories, not lived ones; a pass is one hidden check on a small fixture; the machine was shared, so seconds are noisy; the comparison with seeds 11 and 13 is across different histories and is descriptive, so the change from 4 to 8 passes cannot be credited to P2-13 (there is no arm with the old code on seed 15, and the earlier runs differ in seed); there was no no-hook arm, so the prompt hook's own contribution is not separated from the retrieval changes; the prompt sentence and the harness's scope sentence are the same in every arm; MemoryKing is compared with two baselines, not with other memory products; sizes other than 2,000 and tracks T2 to T5 were not run, so nothing here says how MemoryKing handles corrections, deletion, scopes or injection.
